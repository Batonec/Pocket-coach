Жёсткие границы плана — единственное, что сервер проверяет в ответе модели
поверх JSON-схемы, и здесь они записаны целиком: и то, что читает модель, и
то, что исполняет сервер. Ни одной проверки вне этого файла у него нет.

Блок правила «## имя» — это формулировка (абзац до первой строки с ключом) и
строки «ключ: значение»:

  для каждой: <область>     по чему идти; фраза из словаря plan_validator.SCOPES
                            (для каждого: / для: — та же строка, другой род)
  требует: <выражение>      что обязано быть истинным в каждом случае области:
                            сравнения (и цепочкой) и and/or/not над именами
                            области и числами — ничего больше
  нарушение: <текст>        строка для репромпта, слоты {{имя}} из области
  починить: вес := допустимо   как чинить после второго промаха модели: либо
                            «имя := выражение» (имени области с правом записи),
                            либо фраза процедуры из plan_validator.PROCEDURES.
                            Без этой строки нарушение честно уходит пометкой
                            в rationale (resources/plan_notes.md, «unresolved»)

Формулировка уходит модели в системный промпт блоком «ЖЁСТКИЕ ГРАНИЦЫ»
(нумерация — порядок блоков здесь), строка нарушения — в репромпт. Пометки для
атлета про починку — в resources/plan_notes.md под «имя_fixed» и «имя_change».
Что каждая область знает (имена для выражений и слотов), объявлено в словаре;
правило со словом не из словаря, слот без значения и пометка без починки
останавливают сервер на старте, а не молчат.

Блоки без ключей — обычный текст: catalog_only стоит первым пунктом списка для
модели (это свойство JSON-схемы и санитизации, а не правило), reprompt — текст
исправляющего сообщения.

Когда это работает. Файл читается один раз, на старте сервера: блоки
разбираются в книгу правил (plan_validator.BOOK), и каждое слово сверяется со
словарём — опечатка здесь не даёт backend подняться. Дальше всё происходит
внутри одной генерации «Совета тренера» (recommender.generate_with_trace; её
зовут кнопка обновления в iOS, ночной таймер и Coach MCP) в таком порядке:

  1. до вызова модели из истории считаются рамки сессии (plan_validator.Bounds):
     возвратные потолки, сухие группы, потолок сессии фазы;
  2. формулировки блоков уходят модели в системный промпт списком «ЖЁСТКИЕ
     ГРАНИЦЫ» — она читает правила до того, как их проверят;
  3. первый ответ модели: каждое правило проходит по своей области, и где
     «требует» ложно, рендерится «нарушение». Пусто — план принят. Иначе строки
     уходят модели вторым сообщением того же разговора (блок reprompt);
  4. второй ответ: проверка повторяется; что всё ещё нарушено, сервер чинит по

     Генерация из-за правил не падает никогда.

Больше правила никто не читает: ни запись тренировки, ни баннеры, ни недельный

## catalog_only
в exercises[] — только упражнения каталога (id из схемы)

## coverage
крупная группа (грудь, спина, квадрицепс/ягодичные) или бицепс бедра, у которых 10+ дней ноль эффективных сетов, должна получить хотя бы 1–2 подхода

для каждой: сухая группа
требует: подходов_в_плане > 0
нарушение: группа «{{группа}}» больше {{дней}} дней без единого эффективного подхода и отсутствует в плане — добавь хотя бы 1–2 подхода

## return_ceiling
на возврате после перерыва (≥14 дней) вес любого движения — не выше доперерывного рабочего

для каждого: подход с возвратным потолком
требует: тяжесть <= потолок
нарушение: {{упражнение}}: {{что}} {{вес}} кг тяжелее доперерывного рабочего ({{допустимо}}) — возвратная сессия не место для прибавки
починить: вес := допустимо

## session_cap
рабочих подходов в exercises[] — не больше верхней границы коридора сессии текущей фазы (число в КОНТЕКСТЕ); нижняя граница не проверяется — короткая сессия может быть решением

для: план с потолком сессии
требует: всего_подходов <= потолок
нарушение: в плане {{всего_подходов}} рабочих подходов при потолке сессии {{потолок}} для этой фазы — сократи до {{потолок}}, начиная с изоляции
починить: срезать подходы с хвоста до потолка

## reprompt
Твой план нарушает жёсткие границы:
{{нарушения}}
Исправь ТОЛЬКО эти нарушения, сохрани остальную логику и верни полный план заново в той же JSON-схеме.
